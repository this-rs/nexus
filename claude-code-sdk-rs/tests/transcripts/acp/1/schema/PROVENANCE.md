# Provenance of this schema

**Derived from the public specification of the Agent Client Protocol, NOT from a session with a real
agent and NOT generated by any ACP tool.**

- Source: the pages of `https://agentclientprotocol.com/protocol/` (initialization, session-setup,
  prompt-turn, tool-calls, session-modes), read 2026-10-05, protocol version **1** (an integer).
  The JSON examples of those pages are the shapes `messages.json` was written from; the field lists
  of the schema (`/protocol/schema`) were read once and only used where they agreed with the examples.
- No real ACP agent (opencode, Gemini CLI, Zed's agents…) was ever run. No message in `../sessions/`
  was recorded: the transcripts are written by hand from the specification and replayed by
  `src/bin/fake_acp.rs`. opencode and Gemini CLI were not executed at all.
- The adapter is a client: it announces **no** `fs` and **no** `terminal` capability, never sends an
  image, never calls `authenticate`.

## NOT VERIFIED (named in `messages.json` as `not_verified` where it applies)

| Item | Why |
|---|---|
| `usage` of a `session/prompt` result (`inputTokens`, `outputTokens`, `totalTokens`, `cachedReadTokens`, `thoughtTokens`) | unstable in the specification; shape from memory. Whether `inputTokens` includes the cached ones is unknown |
| `session/update` `usage_update` (`used`, `size`) | unstable in the specification; from memory |
| `messageId` of a chunk | unstable |
| `rawOutput` of a `tool_call_update` | named by the tool-calls page, shape not shown |
| `available_commands_update.availableCommands` entries | the page was not read in detail |
| `session/load` result and modes in it | the load page shows the request only |
| that an agent that needs `authenticate` refuses `session/new` with JSON-RPC code `-32000` | from the specification's error conventions, never seen |
| the ids of modes (`ask`, `plan`, `acceptEdits`, `bypassPermissions`…) | the protocol leaves them to the agent; they are conventions of known agents |
| opencode's `<server>_<tool>` spelling of MCP tool titles | from the provider review, not from a session |
| that `opencode acp` / a Gemini CLI configured for ACP start with the arguments an instance gives, and honour `env` / `headers` as arrays of `{name, value}` | never run |
| the answer of an agent to `session/cancel` when a permission request is pending (we answer it `cancelled` first) | specification text, never seen |

## Re-checking against a real agent

When an ACP agent is installed (for example `opencode`), run a session through `AcpProvider` with a
`command` that starts it, record the lines (the adapter's own `canonical_line` output and the agent's
stdout), and compare them with `messages.json`. To adopt a new protocol version: make a sibling
directory `tests/transcripts/acp/<new version>/`, update `messages.json`, re-record the sessions,
and raise `SUPPORTED_PROTOCOL_VERSION` in `src/providers/acp/mod.rs` and `wire::PROTOCOL_VERSION`.
